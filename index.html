SEC OST Accounts

Combined VAT and Non-VAT (NVAT) clients, per quarter — from the Sales Summary file. Edit any cell directly (same as Task Tracker) — saved automatically to the live database. Use the "Show all" dropdown to find who's still missing a value for a particular field (e.g. Q3 Sales) — this excludes actual "0" values (confirmed zero filing), blank only. There's no manual "Add client" here — the Client Registry is the source: every new client added there automatically gets its own row here (Client ID/Name/TIN/Trade Name already filled in), so the two always stay linked. When a new year starts, use "+ Add New Year" to build a fresh set of rows for every Active/0 Filing/For Closure/Annual Client that doesn't have an End of Service Date yet (i.e. still existing and not yet tagged as service-ended) — no need to do it one by one or wait for a new SQL script. Finished quarters are locked: every detail of a quarter (Sales, Expenses, PT / IT Due, remarks and payment notes) is read-only (grey) once that quarter is older than the one being filed so they can't be changed by mistake — use 🔒 Quarter locks to lock a quarter right after it's filed, or to unlock one when an amended return needs a correction.
One row per VAT client (Sales Summary rows tagged VAT for the chosen year). Type each month's vatable Net Sales, VAT-Exempt, Zero-Rated and Net Purchase (you can type a formula starting with =, like in Excel). VAT Due = Net Sales × 12% − Net Purchase × 12% − Tax Paid + Carry-in (same as your Excel). Each quarter's Sales (vatable + exempt + zero-rated), Expenses (Net Purchase + any Non-VAT Exp you add here) and VAT Due flow automatically into the Sales Summary and the 2550Q task's Tax Due in the Task Tracker. A quarter turns READY FOR ENCODING (signal for whoever prepares the SLSP / VAT Relief) once all 3 months have both Net Sales and Net Purchase filled in (0 counts); type who encoded it in Relief done by to mark it done. Carry-in fills itself in (last quarter's negative VAT Due = unused credit); type a number to override, e.g. Q1's credit from last year (negative number, same as the Excel). Finished quarters are locked (grey, read-only) so filed figures can't be changed by mistake — use the lock button above to lock a quarter after it's filed, or unlock it for a correction.
Compare Itemized vs OSD vs the 8% option (individuals) or Itemized vs OSD (corporations), and see the quarterly income tax (1701Q / 1702Q) update as you type. The figures start from the client's Sales Summary row and the 2307s received, but everything here is a what-if — nothing typed here is saved. Rates used (2026): graduated table 0–35%, 8% on gross less ₱250,000, OSD 40%, 3% percentage tax, corporate 25% / 20%, MCIT 2%. This is a planning aid, not tax advice — confirm with the BIR rules and the client's facts.
Log of withholding tax transactions (rental, purchase, commission, etc.) that the client (payor) deducts from a third party they're paying (payee — usually not a client, e.g. a lessor or supplier). Fields mirror the actual BIR Form 2307: Payee and Payor sections each with TIN/Name/Address/Zip, then the 1st/2nd/3rd Month income payment breakdown from Part III. Edit cells directly; saved automatically to the live database. Total is added up automatically from the 3 monthly amounts, and Tax Withheld is calculated automatically from Total × Rate — it can still be overridden manually. Click "Print 2307" on a row to generate a printable Certificate of Creditable Tax Withheld that includes ALL entries for the same payor + payee + year + quarter. Please verify ATC codes and tax rates against the current BIR issuance first before printing/giving it to the payee. Enter/select the Client ID (from the Client Registry) in the first column to auto-fill Payor Name/TIN/Address/Zip — no need to type those again.
Log of BIR Form 2307s RECEIVED by the client (the opposite of the 2307 Register — here, the client is the PAYEE who had tax withheld by another party, e.g. an e-marketplace or customer). This is the source for SAWT / creditable withholding tax to be claimed on 1701Q/1702Q. Edit cells directly. The total tax withheld per filter is also shown below — for a quick quarterly SAWT total. Withholding recorded in the Daily Sales Record doesn't always come with the actual 2307 certificate right away, and isn't always claimed right away either (often not until Q3 or the Annual ITR) — use "May Actual 2307?" to mark whether the certificate has actually been received, and "Claim Status" to track whether it's been used yet or is still batched, separately from WHICH quarter it was received.

Sales Representative Options

Managed list of names that appear in the "Sales Representative" dropdown in Client Registry and the "Sales Representative" column of Sales Summary — so spelling/names stay consistent wherever it's used. Deleting a name here does not change rows already assigned to that name — it just becomes a value that can no longer be picked going forward.

Bulk Reassign Sales Representative

Fixes every Client Registry entry and Sales Summary row that currently has a specific Sales Representative value — including old free-typed names or nicknames — by reassigning them all to a name from the managed list above, in one click. Useful for name cleanups, or moving a departing staff member's clients to someone else.

Clean Up Tax Type Names

Finds Tax Type values recorded on Client Registry and Sales Summary that don't exactly match one of the 5 canonical Tax Types (VAT, Non-VAT, Non-VAT — 8% Flat Rate, Branch, Non-Profit Organization) — e.g. an old free-typed value, a typo, or different casing/spacing — so you can retitle them to the canonical one in one click. "To" is restricted to those 5 so the result is always clean. This also fixes every quarter's auto-computed Percentage Tax Due that depends on Tax Type (see the Sales Summary tab).

Clean Up Tax Option Names

Finds Tax Option values recorded on Sales Summary that don't exactly match one of the 8 canonical Tax Options (8%, Itemized, OSD, BMBE, Branch, Mixed Income - 8%, Mixed Income - Itemized, Mixed Income - OSD) — e.g. an old free-typed value, a typo, or different casing/spacing — so you can retitle them to the canonical one in one click. "To" is restricted to those 8 so the result is always clean. This also fixes every quarter's auto-computed Percentage Tax Due that depends on Tax Option for plain Non-VAT clients (see the Sales Summary tab).

Branch Client ID Numbering

For a client with "Registering Office" = Branch, set its "Main Client ID" to its Main/Head Office client's Client ID No. (in the Client modal, below Registering Office) — this list then auto-fills with every branch that isn't yet numbered off its Main, so you can assign it a clean ID like 5JS-0001-B1, 5JS-0001-B2 in one click instead of an unrelated standalone ID. A rename here also updates that branch's existing Sales Summary rows and 2307 Register entries so nothing gets orphaned.

Relink Unlinked Sales Summary Rows

Finds Sales Summary rows whose Client ID is blank, or doesn't match any current Client Registry entry — e.g. a row created before a Client ID was assigned, or one left behind after a Registry rename — and matches them to a Registry client by exact Client Name, so Name/TIN/Trade Name go back to being sourced live from the Registry instead of showing whatever (possibly outdated or mistyped) text was stored directly on the row. When a Head Office and its Branch(es) share the same Name (the usual case — same legal business, different TIN branch-code suffix), the row's TIN is used to pick the right one between them; if that still can't narrow it to exactly one, it's left for manual review instead of guessing. Anything else unmatched or still ambiguous is listed below as needing a manual Client ID instead.

Zero Out 0 FILING / FOR CLOSURE Rows

Sales Summary rows whose Client Status is 0 FILING or FOR CLOSURE automatically show ₱0 for every quarter's Sales, 2550Q/2551Q Tax Due and 1701Q/1702Q IT Due (locked, like the other computed cells), and zero themselves the moment a row's status is changed to one of these. This one-time tool applies the same zeros to the rows that already have those statuses (older rows still hold whatever was typed before). Rows that currently hold a non-zero value are listed first so nothing real is overwritten by surprise.

Restore Tasks Wrongly Marked N/A

When a client's status is set to NO / CLOSED, or an End of Service Date is entered, the app automatically marks their open tasks N/A. If the client later became active again (or the End of Service Date was removed / moved later), those tasks stayed N/A. This lists every ACTIVE client that still has tasks the app itself auto-marked N/A, and puts them back to Pending. (Tasks someone set to N/A by hand are left alone — change those from the Status dropdown in the Task Tracker.)

Create Missing Tasks (Task Tracker / Filing Calendar)

The Task Tracker and the Filing Calendar only show tasks that exist. A client added to the Registry gets its tasks automatically for the upcoming due dates when saved; use this tool for the rest (e.g. a client that was in the Registry and Sales Summary but never got tasks, or a Forms list that was filled in later). It creates, from the client's Forms list and the filing calendar, every task the client doesn't have yet — nothing existing is changed. Clients with status NO / CLOSED and Branch clients are skipped; filings due before the client’s Bookkeeping start date (or before today when that date is blank) and after an End of Service Date are not created.

Undo Created Tasks (backward filings / branches)

Lists tasks made by “Create Missing Tasks” (or by a new client being saved) that still have nothing typed on them (Pending, no Done by / date, notes, Tax Due, payment, stage or assignee) and should not exist: filings due before the client’s Bookkeeping start date (or before today when that date is blank), and every such task of a Branch client. Tasks you already worked on, and the upcoming ones, are never listed. Removing is permanent (it is written to the history).

Import ITR 2025 (1701 / 1702 annual) into the Task Tracker

One-time import of the “ITR 2025” list (238 clients, 1701 / 1702 for tax year 2025, filed 2026). For every matched client (by TIN) it creates the annual task TY 2025 (filed 2026) — form 1701 for individuals, 1702 for corporations — with the list’s Tax Due and Remarks as notes. DONE … remarks become Done (with the date, and “DONE BY <name>” as Done by); PAID … become Done + Paid (with the payment date); everything else (FOR PAYMENT, FOR PRINT, FOR SEND TO ERWIN, …) stays Pending with the remark as a note. If the client already has that annual task, only its empty fields are filled — nothing typed is overwritten. Clients whose status is NO / CLOSED are listed but un-ticked. Tick / untick clients as needed.

Branch Tag vs. Client Registry Audit

"Branch" on a Sales Summary row's Tax Type or Tax Option is just a free label on that row — it's a completely separate thing from the Client Registry's own "Registering Office" + "Main Client ID" fields, which is what the Branch Client ID Numbering tool above actually reads to assign a 5JS-0001-B1-style Client ID. The two don't talk to each other, so it's easy for them to drift apart. This lists every Sales Summary row tagged Branch (Tax Type and/or Tax Option) whose Client Registry entry ISN'T set up to match — Registering Office isn't Branch, Main Client ID is blank, or the Client ID hasn't been renumbered yet — read-only, for manual review (fix each one in the Client Registry or Settings tools above, whichever is actually correct for that client).
